# Simhae architecture

`simhae-theme` is the representative repository under the personal `spearkkk` GitHub account. It owns the colour source and public application index. Application repositories remain independent because JetBrains plugins, Chrome themes and Zen CSS have different build and release requirements.

## Ownership

- `palettes/palette.yaml`: editable canonical data; the original four palettes and all their colours are preserved.
- `data/ports.json`: stable application IDs, repository and installation URLs, availability, supported variants and optional screenshot paths. Missing screenshots are omitted, not replaced with images from the old theme.
- `web/`: Next.js App Router with Korean and English messages. It reads shared data at build time, not from a remote API on every request.
- `scripts/`: palette validation and explicit snapshot synchronization.
- `docs/`: the maintenance procedure and structural decisions, understandable without a ticket.

IntelliJ, Chrome and Zen keep an identical palette snapshot plus `palettes/source.json`. Dotfiles keeps the same snapshot in its existing `share/themes/simhae/` path, so bootstrap and existing theme generators continue to work offline. Neovim, Ghostty, fish, SketchyBar, Hammerspoon, btop, k9s, tmux, Starship and Alfred are not split into new repositories.

Snapshot synchronization does not rewrite application-specific colour mappings. Those mappings remain the responsibility of each port. A palette change therefore involves an explicit snapshot update, mapping review and application validation.

## Web

The root request redirects using a saved `simhae_locale` preference, then the browser's weighted `Accept-Language`, then English. `/en` and `/ko` are explicit and do not get overridden. Locale pages are prerendered. Language preference redirects are private and uncached. Asset requests never pass through language redirection.

Vercel is the intended host for the `web/` workspace and requires shared files outside that directory to be included in its build. The public website presents the canonical `pelagic` palette under the name **Simhae**, with no variant selection. Other palette records remain preserved internally. After the full-viewport, locally stored AI-generated ocean image, the information panel opens with a localized personal story: a compact, centered h3 heading followed by five left-aligned paragraphs, naming the theme 심해 in Korean and Simhae (심해) in English. The 24-colour palette follows the story, grouped by background/text, syntax/accents and extended colours. The static Kotlin editor preview and application screenshot gallery follow the palette. Each colour presents a localized role label, its original base key and canonical HEX value. Labels describe Simhae’s mapping, including border at `base03`, comments at `base04`, deep background at `base10`, and bright red/orange at `base11`/`base12`; slots are not renumbered to match a different Base24 scheme. The hero has no central title, only a localized scroll link. A sticky hero stays behind the opaque information section as it scrolls upward. On reaching the header, the hero becomes hidden and inert, its layout height collapses to the header height, and document scroll is adjusted to preserve the current content position. The intro scroll distance is removed, so native upward scrolling stops at the start of the information panel and cannot reveal the image again on that mounted page. Before entry, reversing scroll still reveals the image; a new page load starts the intro again. The header remains fully opaque after entry, including after viewport resizing. Once the section reaches the bottom of the fixed header, its viewport stays pinned and native document scrolling moves the inner content. A measured spacer preserves the content’s full scroll distance without a second scroll container. Resize observation updates the viewport and content geometry; focused links and section fragments are revealed inside the pinned panel. A fixed header progressively becomes opaque over the first 60% of the hero height; keyboard focus reveals it immediately. Reduced-motion visitors get a fully visible header and instant anchor navigation. Without JavaScript, the header and native content links remain usable in normal document flow. At the end of the story, the ocean image reappears, remains faintly visible beneath a translucent deep-water veil, and settles over the `base10` surface with the localized `끝.` / `end.` marker.

The story body has a fixed design maximum of **720px** (`--story-content-width`); the centered palette is **900px**, exactly 1.25 times that width (`--palette-content-width`). Both shrink to fit mobile screens. Keep these proportions when extending the page. Palette groups use shadcn Card; each colour is a shadcn Button that copies its canonical `#HEX` value. The upper-right corner folds over 500ms on hover or keyboard focus to reveal a dashed copy affordance. Touch devices show the affordance without hover, and reduced-motion mode removes the transitions. Official shadcn Sonner lives outside the transformed information panel, with bottom-center positioning and an 800ms duration. Clipboard failures show a localized error instead of a success message.

## Migration boundaries

The IntelliJ repository is renamed, but plugin and theme IDs are preserved. Chrome becomes a Git repository; caches and release archives are excluded. Zen keeps its theme ID and existing CSS. Deep Oceanic Next remains unchanged. Public README documents are English; the site supports both Korean and English.
